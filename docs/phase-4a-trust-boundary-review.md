## Disclosure and query conclusions

**Customers.** List and detail expose exactly public_id, name, country_code and is_active. Both scoped queries select only these fields plus internal id for audit/order. No relationship or default eager load is configured. NIF, email, phone, address, payment/credit terms, price-list relationships, delivery/withholding preferences, balances, timestamps and sequential IDs are absent. Search uses name only. Tests search distinctive excluded-field values and receive no results. Resources accept projected arrays and apply explicit allowlists, so added model attributes do not automatically enter responses.

**Catalogue.** List has the approved thirteen fields; detail adds only description. Base price is read directly, represented as a canonical decimal string and checked through signed BIGINT maximum, including values above JavaScript's safe integer range. No negotiated-price service, price-list fallback, stock query or financial join occurs. Tests populate differing negotiated/list prices and confirm base price persists. Stored currency/tax values are preserved without conversion, tax repair or AGT certification. Unsupported stored tax combinations remain representable; malformed schema values fail before success audit, last-used metadata or any partial page is released. Free-text names/descriptions remain intentional plain-text disclosure, not automatic PII scrubbing.

**Search and pagination.** Both ownership predicates precede the grouped catalogue name OR code predicate. Literal bound-parameter strpos/instr behavior is verified with wildcards, quotes, backslashes, SQL-like input, Portuguese accents and non-ASCII text. There is no contact/NIF/description search. Exact code retains case and whitespace. Unknown fields, expansion/relationship parameters, invalid lengths, controls, UTF-8 failures and scalar/array confusion deny with safe 422. The default active selection, inactive detail access, allowed filters, deterministic descending internal ID, bounded pages and empty pages match the contract. Query count remains two master statements regardless of page size. Counts and offset pages are not a cross-request snapshot or export-completeness guarantee.

## Identity, context and enumeration conclusions

The four shared capability entries independently call authorize, enforce production context and scope every query/count by both workspace and legal entity. Direct human and machine calls under homologation fail before master SQL even with deliberately inserted grants, valid IDs or nonexistent IDs. Human/session and machine/external adapters converge on the same projections and domain semantics. Master-data production context does not activate AGT, assign row provenance or create a sandbox dataset.

Machine identity, credential grants, immutable context and capability authority remain distinct. The fixed three-entry permission/scope map requires the selected scope on both parent and credential plus a fresh primary joined authority snapshot. All eight grant subsets are tested; customers-only, catalogue-only and document-only remain independent, and neither-scope grants no access. Current sponsor membership/role/verification/MFA, original membership identity, credential/integration revocation/expiry and parent ceiling remain effective. No browser policy is evaluated by impersonating a sponsor. Existing human view roles/read-only support attribution remain; membership is workspace-wide as signed, narrowed to an entity per operation.

Cross-workspace, sibling-entity, absent/foreign identifiers, altered environment and browser selection cannot broaden a bound machine identity. Added cases give the sponsor an independent Owner membership in a second workspace: the machine still cannot access it, nor match its records through customer name or catalogue code search. Direct authority-withdrawal cases and independent-process committed revocation/grant/sponsor changes deny at the final snapshot. The signed allowance for already-authorized reads to finish after revocation remains unchanged.

New GET/HEAD comparisons show identical safe error objects for foreign versus absent resources, uniform 403 for foreign/absent entity context, wrong environment and missing scope, fresh request IDs, no-store, no resource identifiers in error/audit and empty HEAD bodies even with debug enabled. The inherited sponsor-withdrawal cases also deny generically. 403 versus 404 reflects authorized context versus scoped resource lookup, not existence of an unauthorized target. Syntax errors and credential failures retain their separately signed 422/401 behavior. No stable externally useful target-existence timing oracle was established; this is not a constant-time network guarantee or a production latency benchmark.

## Audit, transport and quota conclusions

Successful customer/catalogue reads validate the full minimized representation, require synchronous durable audit, then update last-used metadata before returning. Read and denial faults cover disabled, buffered, cancelled and throwing audit behavior: no data or ordinary successful denial is released when required persistence fails. Added eight denial-failure cases cover both transports and both methods. Machine causer/kinds identify the Integration; sponsor remains separate authority; no human executor, delegation or workflow is invented. Human denial UUIDs now complete the operation/request distinction while retaining real/effective actor attribution.

Audit contains trusted context, correlation, bounded operation/filter-presence/status/pagination metadata and scoped success resource references. No confidential query text, search hashes, response contents, prices, NIF/contact data, foreign requested IDs or credentials are copied. Query events/logging are suppressed around actual master reads, connection state is restored and binding-bearing QueryExceptions are replaced without an unsafe previous exception. Existing formatter and exception-report tests demonstrate sanitization; the review corrected the separate ambient-header audit path. Protected audit internal subject keys remain intentionally permitted and never become external fields.

GET and HEAD traverse the same validation, authorization, scoped queries, quotas and durable audit. HEAD is bodyless on success and failures. Nonempty GET/HEAD bodies cannot form a second input channel. No ETag/cache bypass, export, relationship expansion, mutation or outbound fiscal side effect exists.

Quota identity is independent of resource path, method, scope, URL entity and credential rotation. PostgreSQL mixed-resource HTTP workers use overlapping rotated credentials and GET/HEAD yet share the integration ceiling. Existing integration and cross-integration workspace contention tests remain. Denied/invalid authenticated attempts consume shared buckets before resource work; over-limit responses contain only generic errors and bounded Retry-After, not target-dependent results. Pre-auth network and unavailable-store behavior remain. Fixed windows permit a boundary burst as already signed; no sliding-window guarantee was added.
