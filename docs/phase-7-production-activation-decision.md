Existing UI acknowledgement is technically enforced per actor/workspace/policy; it is not itself legal approval or business permission. Tenant enablement, active-owner authority, expiry and user acknowledgement must all be valid. Withdrawal must prevent further inference; it cannot retract bytes already transmitted or promise immediate upstream deletion.

## 6. Credential readiness — no provisioning authorized

Before any key is created: identify the account/workspace and accountable administrators; complete commercial/privacy/geography/notice decisions; approve spending and retention; prove secret-store/ACL, monitoring and kill readiness; obtain explicit credential-provisioning and bounded rehearsal authority. Production provisioning additionally needs its own approved deployment purpose; a rehearsal key is not a production authorization.

Use a dedicated workspace-scoped inference credential, separated by deployment environment, owned by the organization rather than shared through a person's development key. A workspace-scoped service-account key is compatible with this transport; an unscoped key requiring an additional workspace header is not. The existing `x-api-key` header remains supported. Do not use an Admin API credential or introduce federation/authentication redesign. [Official authentication and key lifecycle](https://platform.claude.com/docs/en/manage-claude/authentication).

The approved secret manager must deliver an absolute, readable **regular non-symlink file**, outside repository/webroot, accessible only to its runtime owner, with no group/other permission bits. The existing resolver checks file identity and content bounds; symlink-based secret mounts do not satisfy it. Configuration contains only the protected reference, never the key. No key in builds, tickets, shell history, browser, logs or ordinary environment dumps. Restrict host access because application-level controls cannot protect a key from arbitrary privileged host code.

Approve an expiring key and rotation schedule (P7-PC1 proposes 30 days). Rotation: disable inference, create a separately authorized replacement, atomically install a protected regular file/reference, reload/drain workers/config caches, verify under the approved rehearsal procedure, revoke the old key, then seek re-enable approval. Preserve budget identity/liability. Emergency compromise: close database control and network egress immediately, disable/revoke the key, assess disclosure and notify accountable privacy/security responders through their incident process. Do not log the compromised value.

Leave its SAPI/binary/bindir arguments at their real defaults. Record only selected real path/hash, worker SAPI/version and pass/fail. Its fixed `-n -r` probe must return exactly `cli:` followed by that worker's `PHP_VERSION_ID`, within the shared deadline, bounded stdout and no stderr. Confirm process creation is permitted by runtime/container policy.
5. Under the same UID/build, verify `dns_get_record`, `DNS_A`, `DNS_AAAA` work with the selected CLI's `-n` configuration; verify FPM cURL/TLS/CA functionality and required cURL options. Confirm effective flags/control still deny. Repeat for all serving pools and after runtime/image changes. Any mismatch or timing failure blocks activation; do not weaken the resolver.

The one-second DNS/probe gate is part of a two-second connect allowance and eight-second provider transport budget; planning is bounded at ten seconds and interaction at thirty. Proving a binary exists is insufficient if these runtime bounds fail.

## 10. Kill switch, rollback and local behavior

Immediate application gate: authorized on-call/security operator sets `assistant_provider_controls.enabled=false` or `circuit_blocked=true` on the **primary** row for the approved stable budget ID, using the controlled administrative database procedure. Admission is freshly checked before transmission and before result delivery. Do not create an HTTP administration endpoint for this task.

Also set protected effective `assistant.provider.enabled=false` and `assistant.provider.egress_enabled=false`, rebuild/reload deployment configuration and drain/restart relevant workers. Changing an environment variable alone is not sufficient: the source provider flags are literal defaults, and existing worker configuration may be cached. Independently deny provider network egress; disable/revoke the provider key in an emergency. Assign kill authority in advance so incident responders need not wait for routine product approval.

Verify primary control state, every serving pool's effective flags and absence of new provider connections. Run an authorized denial check without credentials/content. An already transmitted request cannot be unsent; do not promise an instantaneous network cancellation from a database update. Fresh checks withhold results after authority loss; network/key controls contain further exposure. Pending liabilities remain reserved.

After pending attempts reach the recovery threshold, the existing `php artisan assistant:recover-provider-attempts` command provides bounded recovery without resend/refund. Maintain attribution/history and account reconciliation. Do not roll back by dropping ledger tables or restoring a database that forgets spend. Restore means remain disabled until liabilities are reconciled.

**Local behavior:** normal authorized application workflows and the five underlying deterministic read capabilities remain intact. Under `UnavailableAssistantPlanner`, the free-text assistant itself is unavailable when inference is disabled; there is no approved offline production planner/test-planner fallback. Users can use ordinary local search/detail workflows. Preserving these capabilities does not authorize inventing an offline NLP mode. A requirement for continued free-text interpretation during provider outage would need a separate Astra design decision.

Re-enable only after incident review, current approvals/profile/pricing, deployment verification and explicit human authorization. No automatic recovery-to-enabled transition.
