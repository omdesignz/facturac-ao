### Deterministic detector contract

Implement one versioned local policy `p7-question-v1`, with explicit table-driven fixtures. Start from valid UTF-8 within the original character/byte limits. Do not decode base64, fetch links, parse files, OCR or query records. Reject Unicode control/format characters, including bidi and zero-width characters, except ordinary spaces/newlines; do not silently strip them. For detection only, use Unicode case folding and accent-insensitive comparison supported by installed libraries; preserve the admitted original text except reference replacement. Fail closed on normalization errors.

First alias admitted ULIDs in both text and reference list; protect the generated aliases during detection. Then apply these deliberately conservative, reproducible rules:

- Reject any remaining ULID matching the existing `AssistantJson::publicId` alphabet/length or UUID-shaped identifier. Reject `@`, URL schemes, `www.`, backticks, braces, PEM/key prefixes and explicit password/token/secret/API-key markers. Reject common email obfuscation markers `[at]`, `(at)`, `[dot]`, `(dot)`.
- Permit numeric text only as a standalone valid Gregorian `YYYY-MM` month, or a standalone four-digit year 1900–2099. **Any other Unicode numeric character outside protected aliases/month/year blocks.** This intentionally overblocks quantities, phone numbers, amounts and many document/tax identifiers. A year can still conceal sensitive meaning; no anonymity promise follows.
- Reject currency symbols and amount markers `AOA`, `KZ`, `USD`, `EUR`, `GBP`, `ZAR`, `BRL`, `CNY`, `JPY`, `CHF` as whole tokens. Existing eight-currency result buckets remain unchanged; no currency filter is added.
- Reject case/accent-insensitive whole-token markers: `nif`, `nuit`, `iban`, `swift`, `password`, `senha`, `segredo`, `token`, `api_key`, `telefone`, `telemovel`, `email`, `e-mail`, `morada`, `endereco`, `rua`, `avenida`, `travessa`, `apartamento`, `postal`, and phrase `numero de documento` / `numero da factura` / `numero da fatura` / `numero da factura-recibo`. Reject explicit submission/request-ID and raw AGT-payload markers (`submission_id`, `request_id`, `agt_payload`). False positives are accepted for this pilot.
- These rules are a minimum exact implementation policy, not permission for Sol to invent a semantic classifier or loosen a false-positive rule. Additional classes or materially different normalization require review. A customer called “Rua Nova” may require ordinary UI search instead.

Run policy before cost reservation or HTTP. Do not persist original/redacted text, matches or aliases, including in errors. Return an application-owned privacy-unavailable response with no reflected input. Existing browser navigation/search/detail remains available under its normal permissions. **Local fallback means that safe refusal and ordinary application workflow, not a new local NLP engine, guessed tool plan or guaranteed assistant answer.** Existing deterministic test planners remain available only to tests, not a production bypass. Retry requires a new user submission and consumes normal admission; no automatic reword/retry.

## 6. Token and cost accounting — P7-PC1 resolution

The installed `laravel/ai v0.11.2` request builder accepts an explicit output maximum but supplies no verified local token counter. Its response parser exposes input/output/cache counts and defaults missing values to zero. Facturac must validate the original envelope first: missing required input/output counts must fail, not become free usage. Native parsing/re-encoding is not evidence of original JSON validity.

Apply independently:

1. Original question: 2,000 characters / 8 KiB; original request body 12 KiB. Entire serialized outbound body at most 16 KiB, including framing/schema/instructions. Count final transport bytes, not just DTO characters; reject, never truncate.
2. Admission estimate `p7-estimate-v1 = final_outbound_UTF8_bytes + 1024`. Reject above **8,192 estimated tokens** before reserving/sending. This intentionally restrictive byte-based proxy is reproducible and includes a framing allowance; it is **not a certified token bound**. Its effective body ceiling is 7,168 bytes. If the fixed schema cannot fit, stop for Astra rather than quietly lifting it. Unicode and JSON escaping tests use actual serialized bytes.
3. Provider maximum output **1,024**. Thinking disabled; tool/cache/batch/extra modalities absent. The plan still has a separate 4-KiB byte cap.
4. Reserve the full **1,000,000-input-token model envelope**, regardless of estimate, at the higher US pricing tier, plus all 1,024 output tokens. With the sealed prices: `ceil(1000000 * 550000 / 1000000) + ceil(1024 * 2750000 / 1000000) = 552816` micro-USD (**USD 0.552816**) per admitted attempt. This overreservation is deliberate; a lower exact-token envelope needs later evidence/review. No refund in this increment, even after a cheap successful response.
5. Retain validated actual input/output tokens and integer estimated charge alongside reserved liability for the attempt, user, workspace and deployment windows. Do not overwrite reserved counters with actual usage. Usage is provider-reported telemetry, not an independent invoice measurement. Unknown delivery or invalid usage records `usage_unknown`, never zero. No text is retained.
6. Actual input above 8,192, output above 1,024, missing/negative/noninteger/overflow counts, any nonzero cache/server-tool usage, wrong model/tier/geography or unexpected billing category: reject plan before local tools; retain reservation; set a durable deployment provider circuit block requiring operator review. Validated within-envelope usage can still be recorded on an anomaly. Malformed values are discarded, not stored. No automatic retry/repricing/release. Existing concurrent admitted attempts retain their own full reserves; recheck circuit immediately before send.

A model-limit or price breach by the provider cannot be absolutely prevented by application code. The guarantee is bounded application admission under the sealed, verified provider contract, plus a circuit breaker on observed mismatch. Activation must verify model envelope, prices and account settings. Fixed bytes/output, atomic maximum reservations and account caps avoid relying exclusively on post-hoc bills. No token-count or models endpoint is called from an interaction; operators may obtain model metadata later under separate activation authorization.
