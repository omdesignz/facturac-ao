# SA1 — narrow Phase 4B / Phase 1 status-authority amendment

Decision date: 2026-10-07. This executes the exact narrow Astra amendment prompt at the end of the original Phase 4B design, as constrained by the user's subsequent explicit fail-closed requirement. Scope is status authority, historical reconstruction, receipt eligibility and API compatibility only. It does not authorize implementation in this review turn.

**PHASE 4B STATUS-AUTHORITY BLOCKER — RESOLVED**

SA1 explicitly supersedes the Phase 1 C04 rule that an unqualified persisted `valid` value or legacy fiscal fallback is sufficient evidence for receipt eligibility. It also supersedes the original Phase 4B recommendation to preserve that eligibility behavior unchanged. Unknown never authorizes a receipt. Existing fiscal evidence is not invalidated, rewritten or destroyed. All unrelated Phase 1–4A decisions remain signed and unchanged.

## Decision and concept boundaries

The implementation partially separated frozen fiscal documents from mutable AGT workflow, but conflated the latter with both authoritative AGT evidence and receipt eligibility. `CurrentAgtState::validated()` is only `status()->value === 'valid'`. `status()` chooses submission status or frozen document fallback. `IssueFiscalDocument::assertReceiptIntegrity()` and the controller's `settleable` flag consume that boolean. They do not inspect the response that supports it. This is an authorization-evidence gap, not proof that existing issued documents are legally invalid.

Four distinct concepts now have explicit authority:

1. **Historical AGT evidence:** immutable protected request/response attempts and normalized observations, with exact document/submission/tenant/environment binding and provenance. Local events support traceability but do not independently prove remote acceptance.
2. **Current operational projection:** the single versioned reducer's evidence-qualified view on the submission aggregate, including uncertainty, workflow and freshness. It can retain a last-known historical V while its current knowledge is unknown. This is not a second fiscal ledger.
3. **Fiscal document state:** draft/issued and immutable issue, signing, print and calculation evidence. Issuance proves issuance; it does not prove AGT acceptance. This amendment neither certifies nor revokes legal fiscal validity.
4. **Receipt eligibility:** a current application authorization decision made from the qualified projection/evidence plus every existing receipt and actor/context/integrity rule. It is not stored as a perpetual grant and is not inferred from an API label.

There is one evidence reducer. Fiscal eligibility is a policy predicate over its output, not a second status engine. `CurrentAgtState` remains the shared facade. The old enum column is retained for workflow compatibility and outbox scheduling; it is not independently authoritative AGT evidence. No controller, API adapter, Vue component or raw status filter may bypass the qualified predicate.

## Exact receipt rule

For each settlement source, `acceptanceEvidenceSatisfied` is true **only if all** of the following hold at the locked primary-database execution boundary:

- The source is an issued, immutable document in the same workspace/legal entity/durable environment as the receipt; unresolved environment is denied.
- Its canonical projection uses a supported reducer version and has a valid same-submission reference to a qualifying authoritative observation. Missing/corrupt/stale cached projection data is not silently repaired during authorization: fail closed and use the explicit rebuild/reconciliation path.
- Reconstruction classification is `authoritative`; current `knowledge=known`, `reported_state=valid`, and `sync=idle`. The authoritative V is for the exact document and acknowledged request identity, from supported consistent response evidence, not a local assignment or an HTTP/queue result.
- No unresolved conflicting evidence, later unknown/malformed/unsupported result, later non-valid authoritative result, delivery/request failure, outstanding claim, due retry/refresh, or integrity quarantine exists. Prior V remains history when any of these makes the current decision uncertain. Ordinary stale age alone is **not** one of these blockers.
- The legacy workflow column is consistent with V (`valid`); disagreement is an integrity conflict to reconcile, never a shortcut around evidence. For new observations this column and the projection update atomically through one reducer/application path. Backfill never repairs an inconsistent column by fabricating acceptance.

`receiptEligible = acceptanceEvidenceSatisfied AND all existing fiscal/source-type/customer/currency/amount/balance/allocation/actor/MFA/context/series/revision/integrity checks`. This predicate is necessary, never sufficient, authorization. The UI selection and final action use the same evidence predicate, but selection is only advisory and cannot substitute for revalidation at issuance. An existing method named `validated()` may remain as a narrowed delegating compatibility alias; it must not retain the old string test. Prefer the explicitly named predicate in consequential code.

| Evidence-qualified condition                                                               | Receipt acceptance-evidence gate                                            |
| ------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------- |
| Authoritative consistent matching V, no unresolved later work/conflict                     | Pass; other receipt checks still apply                                      |
| Same V older than the 15-minute display window                                             | Pass; label the observation stale/historical, not freshly synchronized      |
| Authoritative matching I, request rejection, processing cancellation                       | Deny; these are distinct reasons, not interchangeable legal conclusions     |
| Processing, result 7/deferred query, pending/sending/retrying/received                     | Deny                                                                        |
| Unknown/partial/absent/locally derived/transport-only evidence                             | Deny, even when an old column/event says valid                              |
| New unknown response or sync failure after V                                               | Deny; retain historical V without using it as current authority             |
| Active refresh/operation after V                                                           | Deny until the current bounded operation completes with qualifying evidence |
| Conflicting evidence, unsupported reducer, invalid references or unverified reconstruction | Deny and require reconciliation                                             |
| Frozen fiscal V with no submission/qualifying bound AGT evidence                           | Deny; immutable local evidence cannot replace the missing AGT prerequisite  |

Do not introduce a freshness-based fiscal expiry. The 15-minute threshold is solely presentation policy, not an AGT or legal validity period. Do not add network calls to eligibility checks. A failed synchronization has greater significance than passage of time: it prevents establishing the current evidence-qualified decision under this conservative application policy.

This changes production behavior for bare legacy V values and insufficient/conflicting evidence. A formerly selectable source may disappear from eligible choices, and an already saved receipt draft may fail final issuance. Explain safely: “A validação AGT do documento de origem não está comprovada. Reveja a evidência antes de emitir o recibo.” Do not advise automatic resubmission or alteration of issued documents. Already issued receipts and their settlements remain immutable; do not undo balances or retrospectively revoke documents.

No new AGT prerequisite is imposed on correction issuance here. Actual inspected code enforces reference context for corrections but does not use the receipt acceptance gate for them. Corrections may concern rejected documents; requiring V there would be an unrelated architectural change. Preserve their existing rules, without presenting unknown as a successful AGT authorization. Any future consequential capability requiring AGT acceptance must use this evidence gate and still needs its own approved capability contract.

## Qualifying evidence and historical reconstruction

`authoritative` means sufficient for this application's supported protocol interpretation, not a claim of independently verified AGT digital signatures or legal finality. The parser/schema version, binding and consistency checks are mandatory. Required evidence is the protected matching status response, its hash and request/attempt linkage, supported document result and trustworthy local observation timestamp. A valid request ID plus HTTP 2xx alone is not enough. Status 0/1/2 without the matching document outcome is not enough. A local `Validated` event alone is not enough. Never manufacture an AGT effective timestamp.

For imported history, verify the stored request/response hashes against decryptable original bytes; match the status query's request identity, submission, document number and durable tenant/environment. Check the response against the supported schema: matching V with no contradictory target/request errors; contradictory aggregate result or conflicting duplicate target entries is not acceptance. Do not reinterpret the currently configured connection environment as historical identity. Supported evidence must establish the same binding even when connection settings have since changed.

Reconstruction classifications are persisted in the closed projection: `authoritative`, `partial`, `unknown`, `conflicting`, with `not_applicable` for drafts. `knowledge` retains the Phase 4B presentation facets. Classification is not a new mutable approval switch. Import writes an immutable `legacy_import` observation referencing original evidence and its classification rationale category. Original records retain their exact bytes.

| Historical evidence                                                       | Reconstruction and consequence                                                                                                                                                                    |
| ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Complete, bound, supported, internally consistent response history        | `authoritative`; derive the latest supported outcome through the same reducer. V may satisfy the receipt gate only with all rule conditions above.                                                |
| Incomplete linkage, absent timestamp/hash, missing/undecryptable response | `partial`; current reported state unknown/null, no receipt authorization. Preserve any identifiable historical claim as unverified history.                                                       |
| No AGT evidence or only local status/event/print/signing facts            | `unknown`; never import accepted/valid/rejected from those facts.                                                                                                                                 |
| Registration acknowledgement/transport success only                       | `partial`; delivery acknowledged may be known, document validation remains unknown.                                                                                                               |
| Conflicting response/status/binding/hash evidence                         | `conflicting`; unknown operational conclusion, quarantine, no receipt authorization. Identity conflicts abort the migration before writes as previously specified.                                |
| Sufficient but old observation                                            | Preserve the authoritative historical reported result and observation time; mark freshness stale. Age does not invent uncertainty in otherwise intact evidence, nor imply fresh remote knowledge. |
| Multiple attempts                                                         | Require a defensible ordered history as below; never choose the maximum ID, last `updated_at`, first matching response, or most reassuring result.                                                |

For legacy multiple attempts, require unique attempt identities, consistent request binding and trustworthy non-overlapping start/completion intervals establishing sequential order. Exact duplicate evidence may be coalesced for reconstruction with all source references retained. Missing intervals, unexplained sequence gaps indicating an unaccounted operation, overlap without a durable fence, or uncertain request identity means `partial`/unknown. Opposing terminal results mean `conflicting` even if timestamps order them: the present contract does not establish legal reversal semantics. An earlier transport failure followed by a demonstrably later, complete bound V can reconstruct authoritative acceptance when the stored final workflow agrees and no unresolved work/conflict remains. Nonterminal history is not itself a contradiction. A later unknown/failure blocks the current gate while preserving an earlier V as historical evidence.

No-submission records cannot reconstruct authoritative acceptance through fiscal fallback; do not create a fictional submission. They have unknown evidence for this gate. The lack of enough evidence blocks a new receipt but is not a new assertion of invalidity/rejection. Drafts have no AGT validation state.

## Replay, reconciliation and concurrency

Use the Phase 4B claim/result journal, fencing and primary row locks. A current matching generation can replace unknown with known only through a new complete qualifying observation. Merely changing a status column, replaying an older V, importing a local event or rebuilding cannot do so. A later malformed result makes the qualified projection unknown and blocks the gate without deleting prior known evidence. Late consistent older evidence does not supersede a newer generation; late conflicting terminal evidence creates an unresolved conflict and blocks authorization. All effects and audit commit together.

Rebuild is a deterministic function of the same immutable evidence and reducer version. Repeated replay cannot change eligibility when inputs are unchanged. Newly appended supported evidence can legitimately change the decision; any prior wording forbidding all eligibility changes during rebuild is narrowed to prohibit unsupported or non-deterministic changes. The first migration intentionally withdraws unsupported legacy eligibility. No source fiscal fields, signatures, numbers, print snapshots, settlements, original attempts/events or old notification records are rewritten.

Receipt issuance currently locks source documents but polling locks submissions; those independent locks do not serialize the new authority decision. **Require both:** after existing draft/series locks, lock all source documents in ascending ID order, then their submission aggregates in ascending ID order, reload the projection from the primary and evaluate the evidence gate. Retain locks through the receipt transaction. AGT claim/completion/rebuild must use the same document-before-submission order, locking its bound document before its submission and rechecking the immutable binding. This includes implicit foreign-key locks taken when appending fiscal events: merely avoiding an explicit document lock is insufficient. Those writers must not subsequently acquire a series or receipt lock. Resolve the immutable parent ID before locking, then verify the tuple under the locks; missing or inconsistent parents fail closed. Database/middleware retries must be bounded and must not duplicate external effects. Test the actual lock order against all affected writers.

If a conflicting/unknown result commits first, issuance sees it and fails before consuming a number. If issuance acquires the authoritative submission lock first and passes, the competing result waits; the receipt is authorized against the committed evidence at that serialization point. A later AGT observation does not retroactively rewrite it. This is not a guarantee about unknowable future remote state. A refresh claim uses the same lock so it cannot slip between validation and commit. Keep read selection and final issuance consistent but never trust the selection snapshot.

Reconciliation is an evidence-review path, not a permission to set `valid`. Provide a restricted read-only inventory identifying source references and bounded reason categories, with no secrets/payload output. Operators review protected original evidence under existing access. Recovering missing evidence, appending a reconciliation observation or contacting AGT requires a separately approved provenance/import or existing authorized operation; no manual override/force-valid UI, CLI or raw status mutation is introduced. If evidence cannot be established, the source remains ineligible. A new valid result may resolve simple incompleteness; an unresolved conflict cannot be cleared automatically merely by a later V. Conflict resolution needs separate reviewed evidence and remains outside this implementation.

Migration rollout must inventory counts of newly blocked sources/draft receipts before activation, archive restricted evidence, pause fiscal writers/AGT workers/schedulers, back up, run the deterministic backfill, compare frozen hashes and validate on disposable PostgreSQL first. Never silently grant an exception to keep old flows green. New projection missing/corrupt after activation fails closed. No rolling deployment with mixed old permissive and new evidence-aware writers. Refuse destructive rollback after journal evidence exists; use forward repair and retain later external obligations.

## API compatibility decision

Keep the existing v1 ten-field document response and filter behavior **as an explicitly documented legacy workflow summary**. `agt_status` remains the existing persisted submission enum, with frozen fallback only when no submission exists; `agt_status_source` retains its existing values. No backfill rewrites those labels or imports them as evidence. This preserves wire values, filtering and consumer behavior. It does not preserve the earlier normative claim that these values alone are evidence-qualified current AGT authority.

This is an **explicit semantic clarification/deprecation approved by SA1**, not a silent relabelling: both OpenAPI files must mark the legacy status fields deprecated and describe their exact raw workflow provenance, lack of evidence/freshness assurance, and prohibition as a fiscal authorization decision. Existing test fixtures that assign raw `valid` may still verify this legacy API behavior, but must also demonstrate that the same fixture cannot authorize a receipt or yield authoritative acceptance in the new projection. Returning an already stored historical label is not reconstructing it into an AGT conclusion. No new `valid` label may be invented by migration to fill missing evidence.

The qualified representation stays internal to authorized session/application readers. No new v1 field, unknown enum value, scope, endpoint, error contract or external credential grant is added. A future machine-readable qualified status API requires a separately versioned contract; do not silently replace `agt_status` with the new projection or inject the internal DTO under `documents:read`. Existing integration access remains globally disabled. External enablement remains blocked pending a separately reviewed disposition of this deprecated legacy status surface; this amendment is not release approval.

The compatibility accessor must be explicitly named/documented (for example `legacyWorkflowStatus`) and limited to old v1 serialization/filtering and historical workflow reporting. It is a direct compatibility read, not an independent inference engine. New operational UI badges, receipt source choices and consequential checks use the qualified facade. Workflow scheduler enums may continue to drive the existing delivery loop, but cannot grant fiscal authority. Known/unknown qualified status predicates and legacy workflow filters must have distinct names and exhaustive tests.

## Required regression evidence

- Legitimate issue → acknowledged registration → complete bound matching V → receipt succeeds with all existing checks. Test stale V too: time passage alone does not revoke eligibility. No proof from frozen issue status is substituted.
- Bound I, rejection, cancellation, pending, failure and unknown all deny. Raw `valid`, local Validated event, printed V, missing attempt, transport-only 200/request ID, undecryptable evidence and missing linkage cannot authorize. Safe failure consumes no number or signature and does not enqueue delivery.
- Legacy import fixtures cover authoritative, partial, absent/local-only, transport-only, stale and conflicting histories plus sequential, overlapping, missing and duplicate attempts. Unknown retains no authoritative reported V/I; historical claims stay explicitly unverified. Hash every frozen/evidence record before/after.
- A later unknown/failure/pending refresh blocks after V; an older V cannot undo it. Opposing terminal results stay conflicted; replay cannot clear them. Supported current-generation evidence can resolve ordinary unknown without inventing prior history.
- PostgreSQL independent-process barriers exercise receipt-versus-poll/result/refresh/rebuild alongside all Phase 4B races. Both lock orders of arrival serialize correctly; no unknown-to-eligible window, sequence consumption on denial, deadlock-prone reverse locks, duplicate fiscal operation or partial audit commit. SQLite tests do not substitute for this gate.
- Replay and reconstruction are deterministic, including fixed reducer versions, operation duplicates and as-of freshness. Backfill may tighten eligibility only as specified; repeated identical input does not change decisions. No external effect or history rewriting during rebuild.
- v1 key/type/filter/provenance behavior stays exact; both specs explicitly deprecate unqualified status as an authority signal. A bare legacy API V coexists with a **denied** receipt and unknown internal projection in the same adversarial fixture. No additional fields leak to existing credentials. GET/HEAD, isolation, audit failure, sponsor revalidation and quota regressions remain.
- Retain legitimate receipt allocation/concurrency tests by replacing fixtures that merely assign `status=valid` with complete fake gateway evidence. Do not delete their original fiscal assertions. Add explicit negative tests for those old weak fixtures. List each changed expectation as SA1-mandated tightening, not a test workaround. Preserve correction, accounting and frozen-print behavior.

No external AGT acceptance, reversal, duplicate-registration, cancellation or effective-time guarantee was inferred. Those homologation dependencies and production enablement gates remain open. The application safety decision is complete without inventing those guarantees.
