## Trust-boundary conclusions

1. **Machine identity and secrets.** Two external GET/HEAD routes use a global stateless boundary, no web/session middleware and no browser tenant resolver. Configuration remains disabled by default. Strict bounded bearer grammar precedes lookup; the entire canonical bearer is hashed with SHA-256, compared with `hash_equals`, and unknown selectors get a dummy comparison. Server CSPRNG generates 32-byte secrets. Only digests persist. Disclosure is once, after the outermost transaction commits, and cannot be cloned/serialized. Query persistence suppresses digest-bearing query events/logging and replaces unsafe query exceptions. Malformed, truncated, combined, duplicate, oversized, wrong-scheme, lowercase-selector, unknown, wrong, expired and revoked inputs deny. No recovery endpoint exists.
2. **A1 attribution.** Hidden canonical UUID v4 uses the existing pre-insert unique-ID hook without replacing integer authentication keys. New user creation, registration, social linking and event-suppressed factories are covered. Database uniqueness/shape/update guards supplement model guards. Integration and each credential copy their actual creator's UUID/kind without a user FK. Live nullable sponsor/creator relationships are separate. Rename, anonymization, deletion and reused integer IDs cannot rewrite or reconnect historical attribution. No UUID appears in the external ten-field response or default User serialization.
3. **Effective authority and scopes.** Only exact `documents:read` on both integration and credential can map to `documents.read`. A valid secret is insufficient. Current verified/MFA Owner/Administrator sponsorship, original active membership, parent state, expiry, explicit binding and capability/resource scoping all constrain it. Scope CHECKs and validators reject wildcard/admin/write/aliases/duplicates. Human recurring approval still requires concrete `ExecutionContext`; the machine read interface cannot dispatch it. No scope or registry expansion occurred.
4. **Isolation.** Workspace/entity/environment come from verified immutable records and explicit route equality, never cookie state, query/body overrides or a different membership of the sponsor. Well-formed foreign/absent bindings both return 403 before foreign target lookup. A foreign/absent document inside the binding returns 404. New evidence includes a second entity in the same sponsor's workspace. Context and creator mutation guards and composite ownership/replacement FKs are tested on PostgreSQL.
5. **Fresh sponsorship.** Each capability performs a single joined authorization snapshot using `useWritePdo`, without positive authorization caching or sponsor impersonation. Membership removal/recreation, inactivity, role loss, unverified email, lost MFA, scope removal and expiry deny subsequent use. User deletion nulls live links while preserving snapshots. There is no separate User active flag to test; applicable account removal/anonymization and membership state are covered. Restoring temporary eligibility may restore an otherwise live integration as explicitly designed; revocation never does.
6. **Lifecycle and concurrency.** Parent locking precedes affected credential locks. Current human authority and expected revision are rechecked; one rotation wins, at most two credentials remain live, overlap is bounded, and terminal revocation is idempotent. Tests use independent PostgreSQL processes, not SQLite lock behavior. Concurrent repeated revocation commits one revision/event. Revocation committed before final authorization denies; a read whose final authorization already succeeded may finish, exactly as signed. Last-used updates touch only that field and cannot undo revocation. Fresh human expiry replacement, narrower rotation grants and recent confirmation remain enforced.
7. **Read surface.** Both routes reuse `DocumentCapabilities`, typed commands, bounded scoped queries, the ten-field resource and `CurrentAgtState`. GET/HEAD share authorization, quota and audit; HEAD has no body. Page/per-page bounds, unknown filters, quarantine exclusion, constant query count and provenance are covered by preserved tests. Production-bound reads inspect existing evidence only; no HTTP/queue/notification fiscal side effect is introduced. No public consequential route exists.
8. **Quotas.** Pre-auth IP 120/minute, authenticated integration 60/minute and workspace 300/minute use stable identities and shared database cache locks/atomic increments. Every applicable authenticated bucket is consumed even when another is exhausted. Rotation or route/header tenant changes do not create fresh quota identities. Unknown selectors do not get a distinct response/quota bucket. Forwarded network identity is trusted only from configured proxies. Unsafe stores and dependency failure deny with sanitized 503. Process contention tests prove integration and cross-integration workspace totals. Fixed-window boundaries intentionally permit a boundary burst; no sliding-window guarantee is claimed.
9. **Audit/correlation.** Machine causers remain Integration, with typed real/effective identity, credential reference, immutable bound context and separate sponsor authority; human executor/delegation/approval/automation are null. Lifecycle causer is the actual managing human, including a different administrator on rotation. Creator snapshots are attribution, never authority. Server correlation UUIDs are fresh; validated client correlation is separate. Invalid metadata is neither echoed nor audited. Required audit persistence now handles exception, disabled, buffered and cancelled-save failures. Anonymous failures do not claim an unverified tenant. App redaction is verified through actual Monolog formatting; infrastructure capture remains an external gate.
10. **Migrations.** Neither Phase 3 migration changed in this review. A1 uses bounded 200-row null-only chunks, uniqueness, final NOT NULL/UUID guards and immutable updates. A new 405-user test crosses three chunks, verifies preserved original user columns, distinct v4 identifiers and stable retry assignments on both SQLite and PostgreSQL. This is algorithmic/backfill evidence, not a production-scale downtime benchmark. Existing tests preserve fiscal/session/membership bytes, staged assignments, empty rollback/reapply, and refusal once rows or attribution audit evidence exist. Integration parent/replacement references restrict deletion; nullable human links SET NULL. Maintenance deployment remains required. No production/application database was migrated.
11. **OpenAPI.** Full specification compared with route inventory, controller validation, typed commands, resource fields, error sanitizer and quota policy. It describes exactly two GET/HEAD paths, separate bearer security, explicit context, one scope and no management or mutation surface. 401/403/404/405/422/429/500/503 semantics, challenge, correlation, no-store and Retry-After are retained. HEAD omits response content. The spec corrections above align documentation with runtime; session OpenAPI is unchanged.
12. **Regression quality.** The original 75 cases include behavioral assertions, direct capability revalidation and genuine process races, not just route status counts. Missing body, silent-audit, nested-log, repeated-revocation, multi-chunk backfill, duplicate-header, sole-owner deletion and exact-spec cases were added. No signed decision was weakened to pass tests.

## Remaining release gates and exclusions

No unresolved implementation finding is being delegated to a routine next phase. External enablement still requires explicit approval after evidence for: hosted CI; actual production PostgreSQL version/parity and primary-authority configuration; backup and maintenance-mode A1 rollout including realistic-volume timing; HTTPS/trusted proxies and request-size handling; database-backed quota behavior under hosted workers; audit persistence/retention/access controls; and proxy, ingress, APM and support-export secret redaction. ## Recommended next bounded phase

**Phase 4A — customer/catalogue read capability and disclosure contract, Astra Medium, design only.** This is a continuation of the master roadmap's _read-first API_ stage, not its similarly numbered safe-mutation stage. The original DOCX was read, including mandatory model routing. Current repository state contains only document integration reads; customer/catalogue controllers still resolve browser context, and their policies use mutable `current_workspace_id`. Their records also lack the fiscal documents' environment column. Customer contact/tax fields and catalogue pricing/tax metadata require explicit minimization and environment semantics before new machine scopes are safe.

There is no signed customer/catalogue resource/scopes contract for Sol to implement yet. Astra should define that narrow extension first, then supply a bounded Sol implementation handoff. It should not use this design task to reopen the approved credential architecture, add provisioning or expose the UI payload wholesale. Analytics and AGT diagnostic expansion remain separate because aggregates and safe diagnostics have additional semantics. Operational release gates do not prevent design or disposable testing, but still prevent external enablement.
