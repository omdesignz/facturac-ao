# Phase 0 Prototype Coverage

The prototype validates information architecture and high-risk fiscal interactions. It intentionally uses representative data and does not persist, sign, submit, or import fiscal records.

## Design direction

The interface is a calm fiscal cockpit: dense enough for accountants, but with a guided primary path for entrepreneurs. A deep mineral-green navigation rail, warm compliance accents, strong numeric typography, and restrained motion distinguish fiscal state from ordinary business data.

The application supports light, dark, and system appearance. Fiscal print templates remain independently controlled and are not affected by the application theme.

## Journeys

### 1. Company onboarding — `/onboarding`

- Shows completion and the legal setup sequence.
- Captures representative NIF, tax regime, CAE, establishment, and address fields.
- Separates taxpayer-key and software-producer-key readiness.
- Calls out that production activation depends on homologation.

### 2. Fiscal dashboard — `/dashboard`

- Shows sales, receivables, AGT pending items, and available series capacity.
- Includes an ECharts sales/collections trend with an accessible summary.
- Surfaces compliance readiness and recent documents.
- Provides quick links to invoicing, imports, and AGT operations.

### 3. Invoice composer — `/documents/invoices/create`

- Provides customer, series, currency, date, line, IVA, and totals controls.
- Calculates representative totals in the browser using decimal-safe cent values.
- Shows fiscal preflight checks before opening the issue confirmation dialog.
- The final action is labelled as a prototype and cannot create a fiscal document.

### 4. AGT status centre — `/agt/submissions`

- Separates received, processing, valid, invalid, and contingency states.
- Shows `requestID`, submission UUID alias, attempts, timestamps, and errors.
- Demonstrates selection of a submission for a complete processing timeline.

### 5. Import workflow — `/imports`

- Supports representative Excel, CSV, SAF-T, and application-migration sources.
- Demonstrates upload, mapping, validation, and confirmation steps.
- Shows duplicate, warning, and rejected-row outcomes before any commit.

## Prototype acceptance criteria

- Every journey is reachable through Inertia links generated by Wayfinder.
- The mobile sidebar is keyboard accessible and traps focus through Headless UI.
- Appearance can be changed between light, dark, and system modes.
- Pages have a single Vue root element and meaningful document titles.
- No control claims that AGT has validated data when it has only been received.
- Representative keys, NIFs, request IDs, and fiscal values are synthetic.
- Type checking, linting, production build, and feature tests pass.
