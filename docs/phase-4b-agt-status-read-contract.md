## B1 — signed current-state/eligibility coupling needs an explicit amendment

Phase 1's “AGT state projection” section makes persisted submission status authoritative, maps `valid` to validated, permits frozen document fallback only without a submission, and requires receipt eligibility and readers to agree. Phase 2 exposes that value as **current** `agt_status`, with only `draft`, `submission` or `legacy` provenance. It has no evidence-confidence or freshness fields. `CurrentAgtState::validated()` literally tests that value for `valid`; `IssueFiscalDocument` uses it for settlement eligibility. `AgtSchemaTwoContractTest` exercises this coupling for every submission enum case. Legacy fallback is an intentional signed behavior, not an automatically removable defect.

The new requirement also says records that cannot be reconstructed confidently must become unknown and stale historical state must not be represented as current AGT state. Existing `status=valid` alone does not prove which response produced it, when AGT observed it, or whether overlapping attempts were ordered correctly. Attempts may be absent or insufficient; existing events do not carry operation fences. An old `updated_at` is not a synchronization timestamp.

Two shortcuts are prohibited: silently downgrade signed eligibility during backfill, or preserve the old value as “current” while introducing a second authoritative status engine. Merely naming the second value a projection does not resolve the contract conflict. Adding a freshness timeout to receipt authorization would also be a new fiscal rule with no homologation basis.

**Recommended narrow amendment:** separate the last recorded workflow/validation decision used by the existing fiscal eligibility policy from the evidence-qualified operational read state. Preserve receipt/correction behavior in this phase; explicitly call the former a compatibility/eligibility decision, not a claim of fresh AGT observation. Authorize unknown evidence and stale qualified presentation for reads. Decide explicitly how the existing ten-field document API ceases to promise a freshness-qualified current state: retain it as a documented legacy workflow summary until a separately approved versioned read representation, or authorize a versioned replacement. Do not silently rename or change the meaning of a signed public field.

This recommendation leaves frozen evidence, tenant/environment boundaries, credentials and scopes intact, but **does change the signed C04 interpretation and Phase 2 field semantics**. The user required preservation of those decisions; it is therefore presented for explicit Astra amendment rather than adopted here. Sol must not decide this boundary. No Sol implementation handoff is authorized until the amendment identifies the treatment of all existing `valid`/legacy cases and the API compatibility choice. Insufficient evidence does not establish that any historical fiscal document is invalid.

## Proposed authority model

Five separate concepts must be represented, even where existing names overlap:

| Concept                   | Authority                                                                                       | Meaning                                                                                                                                                                              |
| ------------------------- | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Fiscal state              | Frozen issued document/print/payload evidence; draft state while mutable                        | Issued is not validated. Changes in AGT communication never rewrite fiscal evidence.                                                                                                 |
| Delivery/workflow         | Committed local operation claims and outcomes on the submission aggregate                       | Queued, sending, retry scheduled, acknowledged, stopped. Acknowledged means registration response supplied a recognized request identity, not fiscal acceptance.                     |
| AGT-reported state        | Recognized, matching, schema-versioned status observation linked to protected response evidence | V, I, processing, processing-cancelled, or unknown. Result 7 means defer query, not a fresh report of processing. Codes 0/1/2 alone do not establish an individual document outcome. |
| Derived operational state | One deterministic reducer over eligible observations and local workflow                         | What Facturac can responsibly say now, including confidence, pending work, synchronization failure and stale evidence.                                                               |
| Explanation/action        | Versioned local vocabulary applied to structured state                                          | Human guidance, not raw upstream text and not authority to execute an action.                                                                                                        |

“Validated” means AGT **reported V for this document in the identified observation**. It is not legal advice, irrevocability, proof of current remote state forever, or a promise that no action can ever be necessary. “Invalid” requires a recognized matching I. “Request rejected” is delivery/request processing, not necessarily document invalidity. “Processing cancelled” is not fiscal cancellation. “Pending” always specifies delivery or refresh. “Needs attention” is Facturac's classification, not an AGT code.

Unknown results, contradictory V plus error evidence, duplicate conflicting target entries, missing target, unsupported schema and unexpected response shapes never become reassuring known states. Preserve the protected response and previous recognized observation separately. Do not expose the unrecognized string as an enum, reason or human message.

## Proposed persistence model

**Keep the canonical mutable projection on the existing unique `AgtSubmission` aggregate.** Do not put it on frozen `FiscalDocument`, and do not create a competing document-status table. A document without a submission has an explicit no-observation view derived from the absence of an aggregate; draft and legacy evidence remain separate provenance. Do not fabricate submissions for historical documents.

Proposed additive schema, subject to B1 and a subsequent bounded handoff:

1. Submission control fields: nonnegative `operation_sequence`, nullable active operation UUID and lease expiry, nonnegative `projection_revision`, reducer version, and closed versioned projection JSON. Database checks constrain allowed versions/required scalar types. Projection JSON is composed only from normalized enums, booleans, timestamps and same-submission evidence references. Existing `status` remains the compatibility column pending B1; its post-amendment writer/mapping must be specified before implementation.
2. Append-only `agt_submission_observations`: internal key, random operation UUID, submission/tenant identity, increasing operation sequence, event kind, schema/reducer version, trusted start/observed/recorded timestamps, nullable validated upstream effective timestamp, normalized closed outcome, nullable attempt FK, canonical outcome hash, and bounded system audit/correlation envelope. No raw response or remote message in normalized JSON. Immutable claim and result entries share the operation UUID. Unique `(submission, sequence, kind)` and `(operation_uuid, kind)` identify ordinary claim/result entries. Conflict entries have a separate random identity and deduplicate by operation plus outcome hash.
3. Tenant composite FKs bind observation to the submission, attempt and its document. Environment derives from the submission's immutable environment; redundant environment, if stored for indexing, must be FK-bound, never caller-supplied. Add only indexes needed for `(submission, sequence, kind)` replay and scoped operational reads. Unique operation UUID is global. Evidence reference keys never become public IDs.

Claims are immutable journal entries, not placeholder attempt rows updated later. Existing attempts remain append-only response evidence; use the captured claim sequence as the attempt number. A terminated operation can have a claim without a result. A late result can be stored for that original operation after lease expiry. New journal rows cannot be reassigned, updated or deleted through application SQL; PostgreSQL constraints/triggers must enforce this, with equivalent SQLite tests where supported. New references use restrictive deletion. Changing deletion behavior for historical tables wholesale is outside this proposal; operational retention must prohibit destructive fiscal-parent deletion.

The persisted projection includes: last applied operation sequence/result reference; last recognized AGT observation reference/state; latest synchronization outcome; last successful synchronization time; whether a current claim is outstanding; delivery state; confidence/source; fixed reason category; projection update time/version. A known state cannot exist without its qualifying observation reference. No untrusted caller may directly set these fields.

`observed_at` is the application's completion time of the response, not an AGT timestamp. `effective_at` stays null because the inspected status DTO does not supply a trusted remote effective time. `recorded_at` is journal insertion time. `projected_at` is projection update time. `last_successful_sync_at` advances only for an eligible, successfully parsed status query establishing a recognized target state or recognized processing/cancelled response—not HTTP 200, registration acknowledgement, result 7, missing target, local queue completion or parser failure.

## Ordering, retries, terminal states and recovery

Use one primary-database row lock for both registration and polling claims. Check immutable workspace/entity/environment/connection agreement, workflow eligibility, due time and active lease under that lock. Allocate a monotonic sequence and random operation UUID, persist the claim and lease, commit, then perform existing I/O. No network call is made while holding the transaction. Capture the request identity/hash in the claim; a poll cannot switch to a later request identity.

Completion locks the same aggregate, validates claim binding, appends the normalized result plus encrypted attempt evidence, and applies the reducer atomically. Exact duplicate operation/outcome is a no-op: no second attempt, transition, notification or audit success. A different outcome for the same operation is an integrity conflict: preserve both protected outcomes, append one deduplicated conflict entry, make the read projection uncertain and flag investigation. Never silently overwrite the first result.

Only the active, matching generation can advance ordinary state. Older or expired/superseded results remain history and cannot refresh freshness, replace request identity or overwrite a newer projection. Local claim order is a deterministic application precedence rule; it does **not** prove remote effective order. A conflicting late terminal report marks evidence uncertainty without promoting that older report to current truth. Two overlapping HTTP calls cannot produce two authoritative results for one generation.

Registration and polling share this fence. Once an acknowledged request identity exists, stale registration outcomes cannot replace it or restart delivery. Registration retries reuse frozen bytes and identity under existing rules; this design grants no new retry command, network route or remote exactly-once guarantee. Uncertain acknowledgements remain uncertain. AGT duplicate-registration/replay semantics require homologation evidence.

The current terminal enum stops automatic work; it does not prove legally irreversible AGT states. Preserve existing stop/dispatch eligibility until B1's mapping is approved. A terminal guard must not discard late evidence. Queue `failed()` callbacks must carry or resolve the exact persisted operation identity; a callback without that identity cannot change authoritative state. Failed callbacks from superseded operations are historical local failures only.

Lease duration remains the existing two-minute recovery window initially, measured using the database clock. Claim identity, not `updated_at`, determines expiry. Recovery uses the existing due-submission outbox dispatcher; do not add a new public refresh operation or increase the allowed operation set. After-commit dispatch is an optimization: committed due work survives dispatch failure. Worker termination before result commit leaves the claim recoverable; termination after commit makes redelivery idempotent. State/evidence/audit transaction rollback leaves none of those writes committed. Network success followed by database failure remains an uncertain external outcome and must not be represented as local success.

Notifications must be based on committed authoritative transitions, with operation identity preventing duplicate transition scheduling. Do not promise exactly-once email delivery from queue dispatch. Persisted notifications and old events are historical and must not be rewritten. New cancellation/unknown notifications must not reuse “document rejected; issue a correction” text. No notification is sent by a read, migration or rebuild.

Rebuild uses the same versioned reducer in sequence order, with observation kind precedence defined in code and tested, and no wall-clock-dependent replay decisions. Read-time freshness is evaluated separately. Rebuild into a candidate value under a row lock or revision CAS; compare canonical projection hash and verify evidence references before replacing it. It must not write attempts, duplicate fiscal events, send notifications, change eligibility, invoke AGT or advance successful-sync timestamps. Concurrent result commit invalidates the candidate revision and causes a bounded retry. Reducer upgrades require an explicit versioned migration/review, not reinterpretation of old evidence by a changed default.

## Freshness and safe explanations

Persist evidence and scheduling facts; compute time-relative freshness at one supplied `as_of` instant through `CurrentAgtState`, shared by object and SQL predicates. Do not persist a `fresh=true` bit that expires without a write. Proposed v1 observation freshness window is **15 minutes**, an application display policy only, not an AGT SLA or fiscal validity limit. Equality at expiry is stale. Clock regressions/future observation times are uncertain. No automatic poll is created to keep terminal documents fresh.

Keep independent fields rather than one overloaded enum:

- `knowledge`: `not_applicable`, `never_known`, `known`, `unknown_response`, `conflicting_evidence`, `legacy_unverified`.
- `sync`: `idle`, `pending`, `failed`; pending requires a durable claim/due operation, not browser activity.
- `freshness`: `not_applicable`, `unverified`, `recent_observation`, `stale`.
- `reported_state`: nullable `valid`, `invalid`, `processing`, `processing_cancelled`; always qualified by observation time/source. Keep a separate last-known value when the latest response is unknown or failed.

Thus a previously known V can be stale with refresh pending, or stale with synchronization failed, without being called invalid. Never-synchronized is distinct from failed synchronization after a prior report. “Recent observation” avoids promising instantaneous remote truth. Result 7 can mean pending query without advancing the prior observation time.

The human representation has fixed local reason codes and translations. Messages contain no interpolated response text, request ID, endpoint, customer fields, NIF, error-code string or exception. A bounded action is advice, not an executable URL/tool/permission. Retryability is `scheduled`, `not_scheduled`, or `unknown`; do not expose a misleading `can_retry` authorization boolean.

| Reason                  | Human meaning                                                           | Recommended action                          |
| ----------------------- | ----------------------------------------------------------------------- | ------------------------------------------- |
| `not_submitted`         | No AGT observation is available.                                        | `none` for draft; otherwise `review_status` |
| `delivery_pending`      | Delivery is queued/in progress; validation is unknown.                  | `wait`                                      |
| `delivery_acknowledged` | Submission was acknowledged; document validation is not known.          | `wait`                                      |
| `processing_reported`   | AGT reported processing at the displayed observation time.              | `wait`                                      |
| `validation_reported`   | AGT reported this document valid at that time.                          | `none`                                      |
| `invalidity_reported`   | AGT reported this document invalid.                                     | `review_document`                           |
| `processing_cancelled`  | Processing stopped; this does not establish fiscal cancellation.        | `contact_support`                           |
| `request_failed`        | Communication/request could not be completed.                           | `review_status`                             |
| `refresh_pending`       | A recorded status refresh is pending.                                   | `wait`                                      |
| `sync_failed`           | Latest synchronization failed; any earlier report is historical.        | `review_status`                             |
| `stale_observation`     | The last report is outside the observation window.                      | `review_status`                             |
| `unknown_response`      | The response cannot establish a supported state.                        | `contact_support`                           |
| `evidence_conflict`     | Available evidence conflicts.                                           | `contact_support`                           |
| `legacy_unverified`     | Historical state lacks sufficient reconstructable observation evidence. | `review_status`                             |

Primary explanation precedence: conflict, unknown response, legacy uncertainty, sync failure, refresh pending, stale observation, ordinary known/workflow state. Return the independent facets too; precedence must not hide stale or failed metadata. No reason advises issuance, resubmission, correction, receipt, cancellation, credential rotation or autonomous action. Fixed categories can classify communication, unsupported response and integrity failures; detailed HTTP/upstream error codes remain protected, even if their strings pass a regex.

## Migration and reconstruction safeguards

No migration is authorized now. A future bounded implementation must use maintenance with web mutations, AGT workers and schedulers stopped; inventory and backup first. Never run a backfill against a live application database as a test. Verify document/submission/connection tenant/environment agreement and preserve unresolved quarantine. Any identity conflict aborts before schema mutation; status uncertainty produces explicit uncertainty rather than invented history.

Inventory hashes of issued document attributes/payloads, print snapshots, frozen requests, attempts, events, grants and credentials. Add columns/table/constraints transactionally on PostgreSQL. Backfill records are distinctly `legacy_import` observations with current import time and original source references; never pretend they are historical network claims. Old sequence numbers/timestamps are not new operation fences.

Historical event plus status alone is insufficient for a verified remote observation. A candidate recognized state requires decryptable matching attempt evidence, correct tenant/document/request binding, a supported parser, internally consistent response and trustworthy local observation time. Ambiguous ordering, duplicate conflicts, unavailable encryption keys, missing attempts, mismatched hashes or missing timestamps produce `legacy_unverified`/unknown. Preserve original evidence and a restricted diagnostic category. Do not infer AGT effective time. Even a reconstructable old report starts stale when beyond the window.

Reconstruction must not modify existing frozen or append-only rows, manufacture successful synchronization, rerun registration, or issue notifications. B1 must determine compatibility-status/eligibility treatment before any backfill can run. Test a populated migration twice for idempotence and compare every pre-existing evidence byte/hash. Verify statement counts and lock duration using representative disposable PostgreSQL data; report actual query plans for scoped lookups and replay, without claiming production performance from small fixtures.

Rollback is allowed only before new journal/projection evidence exists and after verifying no application has used it. Populated destructive `down()` must refuse. Use reviewed forward repair after activation. Restoring an old backup after network delivery is not a safe automatic rollback; operational recovery must retain later external obligations. Production backup/rehearsal, retention and database-role restrictions remain operational gates.

## Disclosure, shared capabilities and API decision

**Recommended bounded exposure: internal qualified projection first; no new HTTP surface or scope in this implementation.** B1 must settle legacy API wording/compatibility before approval. Existing `documents:read`, `customers:read`, `catalogue:read` grants acquire no new fields, history, explanations or authority. Future agents have no entry point or delegated authority. No wildcard scope is introduced.

Proposed application read is a typed `CurrentAgtState` snapshot consumed through the document capability layer, never a serializable Eloquent model. Machine principals must remain ineligible for the new snapshot until an explicit capability/scope contract is approved. Existing session presentation may consume only the bounded human fields under its existing document-view policy; detailed diagnostic access is not inferred from possession of document-read credentials.

Future-compatible closed DTO: `version`, public document ID, fiscal state, delivery state, qualified reported state, knowledge, sync, freshness, observed/effective/last-successful-sync/as-of timestamps, and explanation `{code, message, action, retryability}`. No internal IDs, submission/request IDs, operation UUIDs, response hashes, upstream codes, connection identity, endpoints, payloads, signatures, stack traces, signing material, customer/contact data or arbitrary strings. Provenance is a bounded category (`local`, `agt_observation`, `legacy_unverified`, `none`); detailed evidence linkage stays in protected storage. Null timestamps are meaningful and never replaced with `updated_at`.

Any future exposed capability must authorize before lookup, revalidate sponsor authority on the primary, intersect identity/scopes/context/capability permission, and scope the document **and** submission/evidence by workspace/legal entity/environment. Both known production and homologation fiscal records are legitimate read contexts; Phase 4A's master-data production-only rule does not apply. `unresolved` remains unavailable. Foreign and absent records have identical scoped 404 behavior after valid context; invalid context/missing capability denies uniformly before lookup. No mutable browser selection or sponsor impersonation for machines.

No new list/search/filter/pagination contract is needed for this internal detail snapshot. Existing document list/detail GET/HEAD, pagination, filters, body rejection, no-store, correlation, generic errors, durable audit and shared quota behavior remain unchanged. Reads never query AGT or repair/write a projection. Missing/corrupt projection returns bounded uncertainty, not an opportunistic rebuild.

Do not add new OpenAPI paths, scopes, enum members or fields now. After B1, both existing specifications must accurately document whether `agt_status` is a legacy workflow summary; a future qualified representation needs a separately approved closed schema, timestamps/nullability, matching GET/HEAD and audit behavior. Internal DTOs are not silently added as public OpenAPI components implying support. Existing credentials must not gain additional disclosure through default model serialization.

## Audit and redaction contract

Projection transitions/rebuild/import record trusted system actor kind and operation/correlation IDs, workspace/entity/environment, reducer version, evidence reference, outcome category and projection revision. The system acts only on the previously committed bounded outbox task; it never impersonates the issuer, sponsor or creator. Fiscal actor identity remains in immutable historical evidence. Rebuild/import identify the authorized operator separately from system execution. No agent, delegation or approval is invented.

Journal/projection/audit persistence is one transaction. Required audit failure aborts the state transition; it must not produce a successful state with missing attribution. Local operation UUID and request correlation are distinct. Retries keep operation identity only for the same attempt outcome; a newly authorized claim gets a new sequence/UUID. Replayed results do not produce duplicate transitions.

Use explicit allowlists for audit fields; no raw queries, header values, request bodies, response messages, secrets or unknown upstream strings/hashes of confidential text. Protected evidence bytes stay encrypted in existing attempt storage; no extra plaintext copy in projection, logs or queues. Existing integration redaction and required read/denial audits remain. A future read capability must validate its complete minimized representation before successful audit/use metadata, fail closed on audit failure and keep denied target identifiers out of audit. No external new quota identity is introduced; eventual status reads must share the established integration/workspace buckets across scopes, credentials and GET/HEAD.

## Required acceptance criteria before implementation approval/review

1. **State/unit:** exhaustive enum and normalized-outcome tables; object/query equivalence at a fixed as-of instant; no acceptance from HTTP, queue, local validation or missing errors. V/I require a matching target and supported consistent schema. Processing 7/8 and cancellation 9 have distinct meanings. Test unknown codes/types, duplicate equal/conflicting targets, V with contradictory errors, missing target and unsupported schema.
2. **Freshness:** exact 15-minute boundary, clock regression/future time, null effective time, pending+stale, failed+known, never-known, legacy uncertainty and unknown after previously known. Result 7/failure/registration/late result/rebuild never advance successful-sync. Terminal age creates no automatic polling or fiscal invalidation.
3. **Disclosure:** poison every stored free-text/error field with secrets, PII, markup, instruction-like text and unexpected model attributes. Exact DTO keys remain bounded; messages come from templates. Logs, exceptions, audit, notifications and rendered props contain no poisoned values. No model-wide serialization. New machine disclosure remains inaccessible.
4. **Isolation/authority:** cross-workspace/entity/environment evidence references rejected by DB and capability tests; homologation reads remain scoped; unresolved denied. Sponsor withdrawal, scope isolation, integration revocation, browser-state changes and direct capability invocation retain Phase 1–4A behavior. No read triggers network, refresh, dispatch, mutation or enablement.
5. **PostgreSQL poll/poll:** independent processes pause after claim and before completion; one active lease wins, duplicate worker cannot allocate a competing active claim. After controlled expiry, the superseded result is retained but cannot replace the new generation or claim its attempt number.
6. **PostgreSQL retry/poll:** registration acknowledgement/request binding cannot be replaced by a late retry; poll cannot start without the bound acknowledged identity; stale failure callback cannot fail a newer successful operation. Assert journal, attempt uniqueness, projection revision and audit together.
7. **Duplicate result:** concurrent identical completions produce one outcome/attempt/transition; differing payload hashes for one operation create bounded conflict without lost evidence. There is no callback/webhook receiver; simulate duplicate internal results, do not add one for testing.
8. **Out-of-order/terminal:** older response after newer recognized/processing/failed/terminal results cannot regress authority or freshness. Late conflicting terminal evidence is retained and uncertainty visible. Test both arrival orders; do not rely on sleeps as synchronization barriers.
9. **Recovery/rollback:** kill worker after claim, after network stub response, before commit and after commit. Existing dispatcher recovers only eligible expired work; duplicate delivery is harmless locally. Inject attempt/audit/projection failure and prove atomic rollback. No claim of remote exactly-once behavior follows from these tests.
10. **Replay:** repeated rebuild gives identical persisted projection/hash at the same reducer version, apart from separately audited rebuild metadata. Concurrent rebuild/result uses CAS/lock and converges. No old timestamps are refreshed, notifications sent, evidence rewritten or eligibility changed.
11. **Migration:** populated SQLite/PostgreSQL fixtures for complete, absent, conflicting, undecryptable and ambiguous history; maintenance failure/rollback; no-evidence rollback permitted and populated rollback refused; all fiscal/credential/history bytes preserved. Raw SQL cannot cross-bind/update/delete new journal evidence. Unknown backfill follows B1's explicit compatibility rule.
