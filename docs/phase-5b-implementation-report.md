## Input and persisted service

The closed external object permits code, name, unit_price_minor, currency_code, tax_treatment, optional description and optional unit_of_measure. Strings only; decoded duplicate members, extra fields, nested values, forbidden stock/ownership/tax aliases and transport violations are rejected by the inherited command boundary. Code is ASCII-trimmed/uppercased with the signed grammar. Name/description use NFC, ASCII-edge trimming, the 255-code-point bound and control rejection. Omitted description becomes null; explicit null/empty description is rejected. Unit defaults to UN and follows the bounded free-label grammar, with no invented registry.

External price remains a canonical integer-minor string from zero through 9223372036854775807, with scale 2 and no float conversion or FX. External currency must be AOA. A new effect locks the primary legal entity FOR SHARE and validates its current currency plus configured AOA availability. Authorized completed replay does not inspect current currency/configuration or the current catalogue row.

The four exact tokens IVA_NOR_14, IVA_ISE_M00, NS_M02 and IVA_ISE_M04 resolve through the authoritative tax enum and a pinned strict round-trip check. Mapping drift prevents a new effect but cannot alter historical replay. Entity regime changes do not infer a different profile. Mutable tax-record/unit-record races are not applicable: this domain stores enum profiles and bounded labels, not relationships to mutable tax/unit tables. Actual legal-entity currency and regime races are tested.

Server-constructed attributes create an active service, tracks_stock false, scale 3, null reorder point and the exact price/tax/context fields. No negotiated-price, stock, inventory, fiscal or payment children are created. Same-code existing products and inactive rows conflict; same name with a new code is allowed and another entity may reuse the code. Named database uniqueness remains the race boundary. Query exception classification uses driver error metadata rather than SQL containing user input; unrelated integrity failures are generic failures.

`ServiceCommands` is the shared typed persistence/required-audit action for the existing UI service-create branch and machine adapter. Human decimal-major prices are converted by bounded string operations and checked before integer conversion. Only the approved description-storage and overflow defects become field validation errors. Valid human currency/tax/form behavior is retained. Product creation, catalogue updates/deletes/imports and existing UI redirects remain unchanged. A false/cancelled save or incomplete persisted profile cannot produce an acknowledgement. Readback validates the complete expected row. Automatic creation logging is suppressed only on that instance and replaced by the required minimized creation audit in the same transaction.

## Atomicity, resources and audit

The existing primary READ COMMITTED protocol, ordered authorization/credential/grant/context locks, real-clock expiration, transaction deadlines and no automatic retry remain in force. Preliminary service authorization is inside the bounded database wrapper. New-effect entity SHARE locking supplements the existing context lock. Exact command/version/origin credential/context must match the executing reservation before persistence.

Creation, required audit, immutable acknowledgement, successful ledger transition, shared capacity and last-used metadata commit atomically. Precommit worker death/fault rolls everything back; response loss or worker death after commit recovers through authorized identical replay. Postcommit revocation preserves committed history while denying a subsequent replay. No recovery worker, lease or abandoned durable executing state is introduced.

The namespace includes stable integration, workspace, entity, environment, command/version and hashed opaque key. Customer/service requests can reuse an opaque key independently, but share integration serialization, capacity and quota budgets. The inherited fixed-minute budgets remain IP 60, integration 10 and workspace 30, across both commands and credential rotation. Capacity remains 100000 retained successful operations of either command. At capacity, both commands reject new effects generically while authorized historical replay works.

Audit covers attempted, authorized, service-created, replayed, conflict, denial and failed/outcome-unknown events, preserving current machine/sponsor attribution, immutable origin snapshots, explicit context and correlation. The service subject is CatalogueItem; cross-command subject substitution is rejected. Properties contain neither service input/pricing nor response bodies, keys/hashes, SQL, uncontrolled headers/User-Agent or secrets. Sensitive service DTO/context serialization is refused and redaction is extended. Errors retain only the normative safe envelope; SQL, partial effects and driver detail are not exposed.
