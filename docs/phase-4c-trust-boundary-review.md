## Boundary assessment

1. **Exact disclosure:** The resource is an explicit allowlist over a separately validated representation, not model serialization. The only data fields are `document_public_id`, `knowledge`, `reported_state`, `synchronization`, `freshness`, `observed_at`, `last_successful_sync_at`, `as_of`, `effective_at`, `provenance`, `explanation_code`, `reconciliation_required`. The envelope metadata is exactly request/workspace/legal-entity/environment public context. Model attributes, relations, appended fields, raw projection additions, internal IDs, hashes, upstream text and signing/credential material cannot be added by ordinary serialization. JSON encoding is checked before success audit and return.
2. **Knowledge is not authority:** No eligibility, permission, issuance recommendation, action or retryability field exists. HTTP 200, known valid, or reconciliation false grants no consequential authority. The fifteen closed explanation codes contain no upstream prose. Receipt authorization still requires the separate SA1 evidence gate and all other fiscal checks under its locks. A regression preserves V1 legacy valid while V2 reports insufficient evidence and the evidence gate denies it.
3. **V1 compatibility:** Original V1 routes/controllers/resources and legacy interpretation remain intact. Canonical comparisons of both V1 specifications with the pre-implementation snapshots, excluding only `description`/`deprecated` annotations, are equal. V2 is explicit opt-in; no substitution, redirect or scope implication. SA1 reader/reducer/worker/receipt runtime is unchanged by this review.
4. **Scopes and context:** `documents:agt-status:read` is independent of document/customer/catalogue scopes and must exist on both the integration ceiling and credential. All sixteen scope subsets are covered. Rotation cannot broaden retiring/parent grants; defaults and existing grants remain unchanged. Primary-database permission revalidation retains original sponsor membership, active owner/admin authority, verification/MFA, credential/integration state and immutable workspace/entity/environment binding. Browser state supplies no authority. New tests give the sponsor independent access to a second workspace or sibling entity and still prove rejection before any fiscal-record query. Both AGT environments are permitted for this capability; master-data production-only rules remain separate.
5. **Projection and mapping:** The reader performs one write-PDO scoped left join over the document and bound aggregate with selected columns, followed by database-clock observation. It does not rebuild/replay history, acquire fiscal write locks, contact AGT or authorize receipts. Mapping retains the signed precedence: draft not-applicable; invalid/missing/unsupported/future representation safely unavailable; conflict explicit; partial evidence insufficient except the narrowly recognized never-known workflow case; authoritative supported state qualified; other workflow/failed uncertainty bounded. Refresh/failure masks retained valid/invalid conclusions as specified. Unknown/future states cannot leak an undocumented enum or raw value.
6. **Time/provenance:** Observation, last successful synchronization, response evaluation and absent effective time remain distinct. Supported observations become stale at the exact 900-second boundary without erasing historical acceptance. `effective_at` remains null. Supported uncertainty can retain a safe historical synchronization timestamp without disclosing its old result. Age alone neither revokes proven acceptance nor grants eligibility.
7. **GET/HEAD and enumeration:** Both execute the same identity, scope, context, lookup, mapping, quota, required audit and last-use path. HEAD returns no body, including errors. No ETag/Last-Modified/304 shortcut. Invalid credentials use the uniform 401 challenge; invalid authority/context denies before fiscal lookup; scoped missing/foreign targets share 404; syntax validation and 405 retain the signed order. Responses retain no-store and correlation headers. SQL observers and exact body/status/header assertions test useful existence oracles; no claim of mathematically constant network timing is made.
8. **Audit:** Machine and sponsor attribution remain separate; each read has correlation, a distinct operation UUID, version 2 and the named operation/method. Successful audit includes only the approved scoped target identifier, not the representation or evidence. Denial omits untrusted target/context selectors. Required audit rejects exceptions, unsaved/cancelled records and buffering; failure withholds data and successful last-use. Success dependency/audit failure is generic 503; required denial-audit failure remains 500. Human support attribution is retained, with R1 redaction added.
9. **Quotas:** IP 120, integration 60 and workspace 300 per native fixed minute remain shared across V1/V2, GET/HEAD, resources, context attempts and rotation. Database-backed atomic locks protect counters; cache failure closes access. R2-normalized aliases use the same integration identity, verified by counter assertions. The independent-process V2 test checks actual per-window counts and the allowed boundary burst, rather than claiming a sliding-window limit. R3 is a harness limitation, not grounds to alter production limits.
10. **Migration:** The sole Phase 4C migration, `2026_10_07_201201_extend_qualified_agt_read_scope.php`, changes two scope CHECK allowlists only. PostgreSQL replacements are transactional. SQLite preserves rows, keys, foreign keys and credential-grant immutability triggers and checks integrity. There is no grant backfill, widening, fiscal rewrite, index or new column. Down refuses new grants or retained V2 activity, including generic authenticated version-2 denial. Populated upgrade/down/refusal/interruption are exercised on both engines. Maintenance with writers paused remains required; concurrent rollback is not promised. No application/production database was migrated.
11. **OpenAPI:** Actual route inventory has one GET/HEAD V2 detail route, not a list/batch surface. Runtime tests cover the signed path, security/context, exact keys/enums/nullability, error/status/header associations and bodyless HEAD. The specification matches the normative embedded contract; all 74 local references resolve. V1 remains explicitly a legacy workflow summary.
12. **Concurrency evidence:** Eighteen V2 cases use real forked processes, fresh connections and barriers at the query/authentication boundaries: poll/conflict/refresh/reconstruction versus read; actual draft issuance; scope/revocation/sponsor withdrawal before versus after final authorization; rotated credentials and native-clock quotas. They demonstrate a complete before/after statement view, not a mixed projection. Reconstruction begins with a missing cache so it is observable. The authorization point is explicit: withdrawal before it denies; a completed authorization snapshot may finish, while a later call revalidates and denies. The other 52 PostgreSQL cases preserve evidence fencing, retries, replay, reconstruction, rollback/recovery, receipt eligibility and isolation. No test substitutes SQLite for contention evidence.

## Next bounded phase recommendation

**Phase 4D: analytics read-contract design, Astra Medium, design only.** The original roadmap calls for analytics in the read-first foundation after documents, customers/catalogue and AGT visibility. No signed analytics implementation handoff exists, so Sol must not implement it yet.

The current `ReceivablesQuery::forLegalEntity` constrains workspace/entity/entity currency but lacks an environment predicate. `AnalyticsController` selects the browser's current workspace and oldest entity, scopes invoicing by document date, and calculates present balances for that cohort. Those are not an external explicit-context contract, a payment-date collections ledger or a historical as-of balance. Phase 1 C11 already holds environment-partitioned and historical analytics pending verified scoped queries. Reuse the underlying arithmetic through approved extractions; do not expose the browser controller wholesale or build a second accounting engine.

The design should choose the smallest aggregate-only surface that existing evidence can support. Preserve immutable machine context, live sponsor authority, independent capability scopes, SA1 uncertainty, currency separation, explicit date semantics and statement/snapshot consistency. Exclude customer/contact rankings or drilldowns, individual fiscal authority and unbounded arbitrary aggregation. Unsupported historical metrics must remain deferred rather than being inferred from today's balances.

Operational prerequisites remain release holds: required hosted checks and production PostgreSQL-version verification; primary/clock/proxy/shared-quota configuration; audit/exception/response-log redaction and retention; populated paused-writer migration, backup/restore and rollback rehearsal; SA1 reconstruction/quarantine reconciliation and frozen-evidence verification; explicit V1/V2 consumer semantics and independently granted scope rollout. Real AGT homologation evidence is still required for claims about upstream behavior. Local tests neither enable production nor certify fiscal compliance. These do not prevent design work, but cannot be silently discharged by it.
